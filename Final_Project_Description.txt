Detailed Requirements
1 Design Specification (30 points)
Class Design- Class Diagram: Clearly show class members and relationships between classes.- Data Member Description: Explain what data is stored, its meaning and purpose.- Function Member Description: Specify function prototypes, detailed descriptions,
and main functions.
2 Program Implementation (50 points)- Main Technical Difficulties and Implementation Solutions/Algorithm Design
Software Structure ( additional deduction if structure is unclear due to poor
specification)- Rational Module Division: Each module performs a single task; reusable
functions separated; classes correspond to real-world objects or design
requirements.- Low Coupling: Minimal interdependence; limited use of global objects/variables;
lvalues, non-const pointers, and non-const references used only when necessary.- Good Encapsulation: Public members and non-const functions used only when
necessary.- Rational Class Relationships: Appropriate use of composition, inheritance, and
polymorphism.- Proper File I/O Usage: Projects with no file I/O must explain why, and
demonstrate file I/O with unrelated data.
3. User Manual (20 points)
System operation instructions enabling users to use the program correctly.
Clearly specify restrictions on operations and input data. Insufficient instructions
will lead to deductions; unreasonable tests based on unstated restrictions will
cause further deductions in defense.
4. Test Cases and Software Usage Screen Recording (mandatory, no score; 1-5
points deduction if missing/unreasonable)
Thoroughly test the program with diverse data and workflows, covering all
functions and branches. Record test cases and results. For game software,
describe test content and include screenshots. Submit complete screen
recording as video file or cloud link. Prepare demonstration data for defense.
5. Summary Report (mandatory, no score; 1-5 points deduction if
missing/unreasonable)
Describe project experience, challenges, and achievements.
Detail AI usage: tasks completed with AI, iterative improvements, and problems
solved.
6. Code Style and Rationality (random inspection; 1-15 points deduction)
Deductions for poor practices: global variable abuse, weird naming, overly long
functions, unclear logic, redundant lines, oversized files.
7. AI Usage Description
Report AI usage in framework construction and implementation, understanding
level, and issues encountered. 1-15 points deduction for over-reliance without
modification or optimization.
